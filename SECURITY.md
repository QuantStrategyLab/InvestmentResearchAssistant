# Security policy

## Reporting a vulnerability

Report through GitHub private vulnerability reporting on this repository, or
through the owner's published GitHub profile contact method. Do not open a
public issue for a vulnerability. Do not include credentials, account
identifiers, private session data, holdings, or watchlists.

Include the affected commit, the impact you observed, and the smallest
reproduction that still shows it.

## Scope

This repository holds research instructions and local contract tests. It does
not deploy a service and it does not hold trading credentials. A report is in
scope when a change here would make a research workflow hide its sources,
claim execution is allowed, or invite a reader to place a secret in git.

Credential storage and rotation stay in the private operations process, not in
this file. Research output is not an order.

## What happens next

The maintainer acknowledges a report on a best-effort basis. There is no bounty
and no guaranteed response time.
